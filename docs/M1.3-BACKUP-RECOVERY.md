# M1.3 — Guest Backup Recovery

## Behavior

- Local progress remains the source of truth while guest backup is unavailable.
- Opted-in automatic saves pause while the browser is offline and resume after its `online` event.
- Transient fetch, 429, and server errors receive bounded exponential retries; after the retry budget is exhausted, the learner can retry manually.
- Authentication expiry clears the invalid guest token and requires backup enrollment again.
- Restore and revoke remain explicit actions and report when the browser is offline.

## Limits

- Pending progress is durable in browser local storage; no separate service worker queue is used.
- Retry state is in memory. Reloading while offline preserves progress and the next app session attempts to sync it again.
- Guest backup remains device-bound, anonymous, and not production-certified. Rate limiting, abuse controls, and account-based recovery remain separate work.

## Acceptance

- Build passes and all Vitest tests pass.
- Chromium E2E covers transient request recovery, offline pending status, reconnect upload, opt-in behavior, restore/revoke, and expired token handling.
