# M1.2 Guest Identity and Sync — Implementation & Security Boundary

## Purpose
Alam Mo Ba? remains **guest-first**. Learners can discover, quiz, and save locally without an account or network. This PR introduces the optional, device-bound backup foundation for future account-based synchronization.

## Delivered
- Flyway V3: `learning_account`, `learning_account_identity`, `learning_guest_credential`, `learning_guest_progress`, `learning_account_progress`.
- `POST /api/v1/guest/sessions`: create a 256-bit random guest capability (only SHA-256 digest stored).
- `GET /api/v1/guest/progress`: fetch guest's own document, version.
- `PUT /api/v1/guest/progress`: upload bounded JSON with an optimistic `expectedVersion`; rejects stale updates with 409.
- `POST /api/v1/guest/sessions/revoke`: revoke the capability; no further access.
- Browser Profile: **Enable guest backup**, **Back up latest progress**, **Restore/merge backup**, **Revoke guest backup**.
- Non-destructive union of learned and saved IDs and deduplicated quiz histories. No account or registration prompt.
- Fixed inherited duplicate `V1__content_and_learning.sql` migration from merged main, retaining canonical `V1__content.sql`.

## Security and privacy model
- A guest token is a bearer secret, NOT a registered identity. It must never be accepted as an account credential.
- Credentials grant access to only that guest record. Expires after 90 days, may be revoked.
- API responses use `Cache-Control: no-store`; do not log raw guest tokens.
- Bearer token lives in the same browser's localStorage to support page reloads; protection depends on same-origin scripting integrity.
- No email, name, birthdate, phone, school ID, or other identifying data is requested.
- No registered-account OAuth or verified-email flow has been enabled; no cross-device recovery is claimed.
- The backup is explicitly opt-in, with visible limitations. Clearing browser data also destroys the device's recovery token.
- Not production certified: rate limiting, abuse protection, recovery strategy, privacy/retention audit, secure deployment/headers, human approvals, and accessibility review still required.

## API example
```http
POST /api/v1/guest/sessions
```
Response contains `token` and `expiresAt`. Include:
```http
Authorization: Bearer <guest-token>
```
Fetch `GET /api/v1/guest/progress` and upload via `PUT /api/v1/guest/progress`:
```json
{
  "expectedVersion": 0,
  "state": {
    "mode": "student", "lang": "en", "grade": "7", "subject": "all",
    "count": 5, "saved": [1], "learned": [2], "streak": 1,
    "last": "2026-11-04", "attempts": []
  }
}
```
