# M1.3 — Opt-in Guest Progress Backup

## Behavior

- Guest learning and local progress remain available without network access or backup enrollment.
- Backup is opt-in from the Profile screen. After enrollment, progress changes are debounced and uploaded through the existing versioned guest progress API.
- Saved facts, learned facts, quiz attempts, streak and last-learned date use the existing non-destructive server merge and 409 retry behavior.
- A local fingerprint avoids redundant writes after navigating between screens. Automatic uploads do not replace in-memory progress with a server response; **Restore/merge backup** remains the explicit action that applies server progress locally.
- Expired guest credentials are cleared and the learner is told to enable backup again.

## Limits

- The guest token remains a bearer secret stored in this browser. It is not an account credential.
- Clearing this browser's site data removes the token; there is no cross-device recovery.
- This change does not enable account registration, identity linking, or cross-device account synchronization.

## Acceptance

- Verify no guest API traffic occurs before opt-in.
- Verify a subsequent local bookmark change is saved while the learner is outside Profile.
- Verify explicit restore and revocation preserve local progress.
- Verify expired sessions clear the token and return the UI to the opt-in state.
- Run frontend build, Vitest, and Chromium Playwright suites.
