# Alam Mo Ba? — M1.2 Remaining Work Plan

Working baseline: merged M1.1 on `main`; M1.2 guest foundation is in draft PR #4.
This milestone is staged to preserve the guest-first experience and prevent unverified account logins.

## Task sequence

| Sub-milestone | Deliverable | Acceptance |
|---|---|---|
| M1.2.4a | Concurrent guest backup recovery (stacked PR #5) | Retry verified on 409, bounded attempts, no lost bookmarks, failed auth not swallowed |
| M1.2.4b | Threat model, guest token and consent review | Rate limits, sensitive-data logging checks, token disclosure and expiry controls verified |
| M1.2.5 | Verified identity login (Google OIDC or verified email link) | Strict state/nonce, issuer/audience/signature/expiry verification; account sessions and revocation; security regression |
| M1.2.6 | Guest-to-account migration | Transactional, idempotent and authenticated import; tenant/account ownership and collision tests |
| M1.2.7 | Multi-device account progress | Versioned concurrency strategy, retry, cross-device E2E, conflict preview and safe merge |
| M1.2.8 | Privacy/security certification | Minor-aware consent, data export/delete, retention, abuse controls, full CI and human review |

## Implementation ordering

- PR #4 introduces anonymous device-bound backup. **Do not treat it as account recovery or Google login.**
- PR #5 is stacked against PR #4 to add **M1.2.4a**. It should be merged only after its base is accepted, or retargeted to `main` after PR #4 merges.
- Avoid passing guest bearer tokens as account credentials. Authentication must be independently verified and account ownership established before any user data is claimed or merged.
- The source of truth remains GitHub; each coding sub-milestone has separately verifiable commits and CI logs.
- PRs stay draft until security and regression gates pass. No automatic merges.

## M1.2.4a tests

- A competing writer changes remote state while saving: fetch latest version, merge saved/learned sets, preserve attempts and retry.
- Server repeatedly reports 409: stop after bounded retries and show a failure.
- Non-409 failures (including HTTP 401) are not retried or hidden.
- Existing backend PostgreSQL and browser guest regression must stay green.

## Limitations

Server-side rate limits, secure account OAuth/email verification, multi-device recovery, identity binding, verified minor consent, deletion and retention remain separate deliverables. Never label the current browser's anonymous backup production certified.
