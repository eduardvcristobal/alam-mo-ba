# M1.3.1–M1.3.5 — Platform Admin & Editorial Publishing

## Scope

The independent platform administration workspace is available at `/admin`, separate from Student Mode and Explore Mode. It is an **admin-only application** backed by the same verified, revocable account sessions used for learner accounts. A session alone is insufficient: every admin API also checks role membership in PostgreSQL.

The application includes:
- M1.3.1 — Verified admin RBAC and trusted provisioning; roles `SUPER_ADMIN`, `CONTENT_ADMIN`, `EDITOR`, `REVIEWER`, `SUPPORT`.
- M1.3.2 — Responsive admin layout, dashboard counters, protected sidebar and role-aware pages.
- M1.3.3 — Draft facts with English/Filipino text, subject, audiences, grades, source title/URL, and draft editing.
- M1.3.4 — Quiz question authoring with English/Filipino prompts, explanations, 2–6 options, one correct answer and parent fact selection.
- M1.3.5 — Editorial status machine with a persistent audit trail and publication gates.

## Roles

| Role | View | Draft facts & quizzes | Review | Publish/retire |
|---|---|---|---|---|
| SUPER_ADMIN | ✓ | ✓ | ✓ | ✓ |
| CONTENT_ADMIN | ✓ | ✓ | ✓ | ✓ |
| EDITOR | ✓ | ✓ | — | — |
| REVIEWER | ✓ | — | ✓ | — |
| SUPPORT | ✓ | — | — | — |
| Ordinary account / guest | — | — | — | — |

Reviewers cannot approve or reject content they authored, regardless of other roles. The database records the editing and reviewing identities. No public admin account creation, role elevation or access-token bypass is included.

### Seed starter facts and quizzes

In `/admin` → **Facts & Content**, a `SUPER_ADMIN` can select **Seed starter
facts + quizzes**. This creates two bilingual science fact drafts and linked
quiz drafts through the normal admin API. Repeating the action skips existing
starter keys and questions. The drafts remain unpublished; reviewers still
need to verify the cited sources and complete the editorial workflow before
learners can see them.

### First administrator on a fresh database

For a single-owner local deployment, set `ADMIN_GOOGLE_LOGIN_ENABLED=true` and
`PLATFORM_ADMIN_EMAIL` to the owner's Google email. Keep public account
registration disabled. On the first successful Google sign-in at `/admin`, the
backend verifies Google's signature, audience, nonce and verified email. If the
Google identity is not yet registered and its verified email exactly matches
`PLATFORM_ADMIN_EMAIL`, the backend creates the account and progress row, grants
`SUPER_ADMIN`, and records the bootstrap in `platform_admin_audit`.

Only that configured identity can bootstrap. Existing identities without a role
are not elevated automatically, and a bootstrap grant is not restored after it
has been revoked. After the first successful sign-in, `PLATFORM_ADMIN_EMAIL` may
be removed; the database role remains until explicitly revoked.

This verified first-sign-in bootstrap is the seed function for the initial
administrator. It only runs when the configured Google identity has no account
yet and does not recreate a role that was later revoked. After recreating the
database, apply migrations, configure the environment, then sign in once at
`/admin` with the configured Google identity. Use **Sign out** in the admin
sidebar to revoke the current session and return to sign-in.

### Assigning operator roles

After signing in as `SUPER_ADMIN`, open **Access & Roles** in the sidebar. The
page lists verified Google email addresses, current roles and account status.
Search and select an email, choose a role and grant/revoke action, enter a
reason, then submit. Only `SUPER_ADMIN` can see account emails. Only active
accounts can receive roles. Changes are written to `platform_operator_audit`;
the UI and API prevent removing your own or the last active `SUPER_ADMIN` role.
A user must sign in to the learner app once before their account appears in
this list. Older accounts need to sign in again for Google to refresh their
verified email.

### Creating a learner account

In the learner app open **Profile** and use **Continue with Google**. The
backend only creates/signs in learner accounts when
`APP_ACCOUNT_REGISTRATION_ENABLED=true`; it is off by default. Set it in the
local `.env` and restart the backend to let a new user register. After they
sign in, their account ID and account appear on the `SUPER_ADMIN` Access &
Roles page. Turn registration off again if you do not want new accounts to
register during normal local use.

### Trusted admin provisioning (manual and auditable)

1. A verified account must already exist through approved authentication. Never grant platform roles to an unknown or unverified identity.
2. An authorized database operator independently verifies the account ID and approves a privileged role.
3. In a controlled DB session:
```sql
BEGIN;
INSERT INTO platform_admin_role (account_id, role)
VALUES ('<verified-account-uuid>'::uuid, 'CONTENT_ADMIN');
COMMIT;
```
4. Verify access using the account's own valid session at `GET /api/v1/admin/me`; check that guest and ordinary learner tokens are denied.
5. Revoke using `DELETE FROM platform_admin_role WHERE account_id = ... AND role = ...`. Existing bearer sessions immediately lose the revoked admin privilege, because every request rereads the role table.

Never seed a password or bearer credential, expose role-grant SQL in an unauthenticated UI, or enable public learner registration simply to access the admin interface. The email bootstrap only accepts a signed Google identity with a verified exact email match.

## Editorial lifecycle

`DRAFT → IN_REVIEW → APPROVED → PUBLISHED → RETIRED`. Rejected submissions return from `IN_REVIEW` to `DRAFT`.

- **Author**: Creates or edits a DRAFT and submits to review.
- **Independent reviewer**: Confirms both translations, audience, and source. Fact approval requires explicit source-checked acknowledgment and timestamps the checked source/verification fields. Quiz approval validates bilingual options and exactly one correct answer.
- **Content administrator**: Publishes APPROVED items. A quiz can be published only after its parent fact is published and source-verified.
- **Public API**: Reveals only PUBLISHED, verified facts and their published quizzes. Correct answer flags and explanations remain hidden until grading.
- **Audit**: Every create, draft edit and editorial transition is recorded with actor, entity, status and timestamp. No UI action allows arbitrary record deletion.

## APIs

All `/api/v1/admin/*` calls require an `Authorization: Bearer <registered-account-session>` header and a matching PostgreSQL admin role.

- `GET /api/v1/admin/me`, `GET /api/v1/admin/dashboard`
- `GET/POST /api/v1/admin/facts`, `GET/PUT /api/v1/admin/facts/{id}`
- `GET/POST /api/v1/admin/quizzes`, `PUT /api/v1/admin/quizzes/{id}`
- `GET /api/v1/admin/review/queue`, `GET /api/v1/admin/review/audit`
- `POST /api/v1/admin/review/{facts|quizzes}/{id}` with action `submit`, `approve`, `reject`, `publish` or `retire`. Fact approval requires `sourceChecked=true`.

No learner role is permitted to use these endpoints.
