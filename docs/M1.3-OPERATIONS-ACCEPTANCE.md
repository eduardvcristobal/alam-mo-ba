## Implemented

### M1.3.6 — Curriculum
- Bilingual subject and topic dictionaries, grade-specific topics (Grades 1–12), active/inactive controls.
- Subject/topic management requires `SUPER_ADMIN` or `CONTENT_ADMIN`.
- Existing fact records remain migration-compatible; assigning a topic is optional, editor-restricted, and permitted only for DRAFT facts whose subject and grade match an active curriculum topic.
- Curriculum is a classification structure, not a claim that material has been certified against an official curriculum.

### M1.3.7 — Learners
- Protected directory shows only pseudonymous account ID, status and account creation date.
- No emails, provider subjects, exact ages, names, individual quiz attempts or learning histories are exposed to support operators.
- Only `SUPER_ADMIN` can enable/disable accounts; a written reason and security audit are mandatory.
- Self-action and alteration of another super-admin account are blocked. Account deletion is handled separately by the authenticated privacy lifecycle.
- Page is deliberately paginated (100-record maximum) to limit bulk access.

### M1.3.8 — Analytics
- Aggregate-only metrics: registered/active/disabled accounts, active guest backups, DB-persisted quiz attempts, published facts/questions, content counts by subject and workflow status.
- `recordedQuizAttempts` counts the server-side `quiz_attempt` table, not all localStorage-only quiz sessions; do not mislabel it as all platform quiz activity.
- No individual identities or progress documents are returned.

### M1.3.9 — Platform settings & audit
- Implemented allowlisted setting `content_submissions_enabled`, enabled by default. When disabled, backend fact/quiz creation returns a conflict while existing approved material remains available.
- Changes require super-admin privileges and a written reason.
- Immutable operator audit rows for learner status transitions and setting changes.
- Other future module flags are intentionally not exposed until they have functional implementations.

### M1.3.10 — Regression
- Real PostgreSQL/Flyway migrations V8–V9.
- Synthetic role-based CI tests verify curriculum topic and grade mapping, learner privacy, super-admin status governance, aggregate analytics, audited setting changes and paused submissions.
- Chromium E2E tests exercise curriculum, learner directory, aggregate analytics and settings in addition to existing learner/admin workflows.
- All test accounts and content in smoke scripts are created in disposable CI PostgreSQL, not a real tenant or production database.
