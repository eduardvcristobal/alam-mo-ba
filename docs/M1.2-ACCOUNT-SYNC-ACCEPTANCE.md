## Delivered

- **M1.2.4b:** Preserved bounded 409 retry, session rejection handling and non-destructive guest progress merging (original stacked PR #5).
- **M1.2.5:** Google ID token validation via Google's JWKs and RS256, issuer, configured OAuth audience, expiry, verified email and one-time server nonce. Server generates 256-bit account session bearer secrets stored only as SHA-256 digests; revocable on logout. Account registration requires both `GOOGLE_CLIENT_ID` and explicit `ACCOUNT_REGISTRATION_ENABLED=true`; remains disabled by default.
- **M1.2.6:** Versioned account-owned progress, account-scoped GET/PUT, one-time guest import with proof of **both** account session and guest secret, atomic transaction, cross-account conflict prevention, guest token revocation and idempotent same-account retry.
- **M1.2.7:** Typed account API client using browser sessionStorage for short-lived account sessions; versioned, conflict-aware progress merge and explicit guest import function. Provider UI remains deliberately disabled until consent gates.
- **M1.2.8:** Account export and deletion endpoints scoped to logged-in account. Deletion requires exact explicit confirmation and a session issued in the last 15 minutes; cascades through account sessions, identity, account progress and imported guest backups. Anonymous backup revoke actually erases guest backup records.
- **Compatibility:** New Flyway V5 repairs legacy V1 audience primary key enforcing a non-null grade for Explore content, without modifying already-shipped migration checksums.

## Configuration

By default `/api/v1/account/google/challenge` returns 503 and account registration is disabled. When external provider, privacy and underage safeguards are approved, the backend may be configured using:

- `APP_GOOGLE_CLIENT_ID` (mapped through `app.google.client-id`, see Spring config)
- `APP_ACCOUNT_REGISTRATION_ENABLED` (mapped through `app.account.registration-enabled`)

These are *deployment prerequisites*, not instructions to enable registration today.
