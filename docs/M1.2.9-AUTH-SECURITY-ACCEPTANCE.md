## Implemented
1. Google Identity Services UI loads only after explicit action and remains hidden by default. Browser build requires both `VITE_ACCOUNT_SIGNIN_ENABLED=true` and `VITE_GOOGLE_CLIENT_ID`; Spring Boot requires `ACCOUNT_REGISTRATION_ENABLED=true` plus `GOOGLE_CLIENT_ID`. **Do not set the registration flag until privacy and security review.**
2. The server issues a fresh one-time nonce to pass to GIS `initialize({nonce})`. Its signed ID token is validated by the backend, including Google JWK signature, issuer, audience, nonce, expiration, and verified email. Backend account sessions are separate from guest backup credentials.
3. Explicit adult-only self-attestation is required to reveal the GIS button. **Self-attestation is not reliable age verification or guardian consent.** Underage registration must remain disabled pending a certified consent design.
4. Following successful account login, existing guest cloud backup can be imported with both its guest token and the verified account token; progress is merged and may be resynchronized from multiple browser contexts.
5. The account interface exposes explicit manual sync, JSON data export, sign-out and account deletion. Account deletion requires exact confirmation; backend requires a freshly issued account session.
6. High-risk unauthenticated endpoints now use PostgreSQL-backed per-minute buckets, with atomic conflict-upsert counting to work across replicas: guest-session creation (15/min), Google challenge (10/min), Google login (10/min). Direct socket remote addresses are hashed; **never trust incoming X-Forwarded-For headers** without a configured trusted proxy.
7. Daily UTC retention cleanup removes expired/consumed login challenges, expired/revoked account sessions, expired/revoked guest backup sessions (cascades guest progress) and old rate-limit buckets.
8. Two-browser-context Playwright scenario verifies that bookmarks from independent browser contexts are safely merged; another test mocks the GIS nonce callback and account synchronization.

## Configuration
Backend (safe defaults):
```properties
GOOGLE_CLIENT_ID=
ACCOUNT_REGISTRATION_ENABLED=false
CORS_ORIGIN=http://localhost:5173
```
Frontend (safe defaults):
```properties
VITE_ACCOUNT_SIGNIN_ENABLED=false
VITE_GOOGLE_CLIENT_ID=
VITE_API_BASE_URL=/api/v1
```
`GOOGLE_CLIENT_ID` and `VITE_GOOGLE_CLIENT_ID` must refer to the *same* Google Cloud OAuth web client ID. Configure exact authorized JavaScript origins in the provider console. Never commit client secrets or bearer tokens.

For a manual *approved* development test, enable the backend registration flag and frontend flag only in an isolated, secured test environment with a controlled Google OAuth app. Verify provider-origin/callback behavior, nonce replay rejection, account lifecycle and real cross-device login. Do not enable for the general public.
